# تطبيق الويب: لوحة التحكم وبوابة العملاء

تطبيق واحد (Next.js 16 + TypeScript + PostgreSQL) يضم لوحة تحكم صاحب المشروع وصفحة تتبع العميل، بالعربية أولًا (RTL). الصفحات العامة للموقع تأتي لاحقًا بعد حسم الاسم، وحاليًا توجد صفحة رئيسية مؤقتة فيها "قريبًا". المواصفات المعتمدة: `docs/build/00-mvp-spec.md`، والافتراضات: `docs/build/01-build-notes.md`، ولقطات الشاشة: `docs/build/screenshots/`.

> **البيع مطفأ افتراضيًا** (`SALES_ENABLED=false`): لا روابط دفع ولا أزرار دفع ولا قبول عروض ولا تسجيل دفعات حتى صدور تصريح العمل. يرى العميل العرض كاملًا مع رسالة هادئة بأن الدفع سيُفتح قريبًا.

## ما الموجود

| المسار | المحتوى |
|---|---|
| `/` | صفحة مؤقتة: اسم البراند من الإعدادات و"قريبًا"، بلا أسعار ولا طلب |
| `/admin/login` | دخول المدير (بريد + كلمة مرور، حد 5 محاولات فاشلة كل 15 دقيقة) |
| `/admin` | شاشة "اليوم": ما يحتاج ردك، والمشاريع المتأخرة، والدفعات المنتظرة، وآخر الأحداث، والتجديدات |
| `/admin/clients` | العملاء: قائمة وبحث، وإضافة، وصفحة العميل مع تعديل بياناته ومشاريعه |
| `/admin/projects` | المشاريع مع تصفية بالحالة، وصفحة المشروع (انظر أدناه) |
| `/admin/projects/<id>/quotes/new` | منشئ عرض السعر: باقة أو بنود مخصصة، دولار أو يورو، خصم، وجدول دفع افتراضي قابل للتعديل |
| `/admin/costs` | التكاليف: إضافة، وسجل الشهر، والإجمالي حسب الفئة والعملة، والالتزامات المتكررة، والتجديدات |
| `/admin/outbox` | صندوق صادر البريد (في التطوير فقط): الرسائل ورموز التحقق حين لا يوجد مفتاح Resend |
| `/admin/settings` | للعرض فقط: البراند، وحالة البيع، ووضع المستندات، وسياسة الدفعات، والبيئة |
| `/p/<الرمز>` | صفحة تتبع العميل بالعربية، و`?lang=en` للإنجليزية |

**صفحة المشروع في لوحة التحكم:** تغيير الحالة (الانتقالات المسموحة فقط، والممنوعة تظهر مع السبب)، وما يراه العميل الآن، وعروض الأسعار (تعديل المسودة، ثم "إصدار وإرسال" يمنح رقم Q ويولّد PDF)، والدفعات (مسودات، ورابط دفع، وتسجيل دفع يدوي مع ملاحظة وملف إثبات يُصدر إيصال R بصيغة PDF؛ كلها معطّلة والبيع مطفأ)، والمستندات وإشعارات دائنة CN، والتسليمات (معاينة تظهر فورًا، ونهائي لا يُفتح إلا بعد سداد كل الدفعات)، وطلبات التغيير (ضمن النطاق أو خارجه مع عرض إضافة)، والخط الزمني مع زر "ظاهر للعميل/مخفي" ورسائل للعميل أو ملاحظات داخلية، ورابط التتبع (إنشاء ونسخ وإلغاء وإرسال بالبريد).

**صفحة العميل:** المراحل السبع مع المرحلة الحالية وشارات "تعديلات" و"طلب إضافة"، والتحديثات الظاهرة، وعرض السعر كاملًا مع تنزيل PDF، والقبول (خانة الشروط + خانة البدء الفوري والتنازل عن العدول + رمز تحقق بالبريد، وتُسجَّل الموافقات)، والدفعات، والمعاينات، والملفات النهائية خلف رمز تحقق وبعد السداد الكامل، وصفحة لطيفة للرابط المنتهي أو الملغى. الصفحة لا تُفهرس (`noindex`) ولا تُسرّب الرابط (`Referrer-Policy: no-referrer`).

## المتطلبات على كل جهاز

- **Node.js 22.12 أو أحدث** و**pnpm 10**: بعد تثبيت Node نفّذ `corepack enable` مرة واحدة، فيُستخدم إصدار pnpm المحدد في `package.json`.
- **PostgreSQL 16**، بطريقة من اثنتين:
  - **Docker** (أسهل على كل الأنظمة، وهو الوحيد المناسب لويندوز): Docker Desktop ثم `docker compose up -d db`.
  - **محليًا بلا Docker** (ماك ولينكس): `pnpm db:start` يشغّل خادمًا على المنفذ 54329 داخل `web/.pgdata`. على الماك: `brew install postgresql@16` والسكربت يجده تلقائيًا. على لينكس: حزمة `postgresql-16`.
- **Google Chrome أو Chromium** لتوليد ملفات PDF (والتطبيق لا ينزّل أي متصفح). ضع مساره في `CHROMIUM_PATH`:
  - ماك: `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`
  - ويندوز: `C:\Program Files\Google\Chrome\Application\chrome.exe`
  - لينكس: `/usr/bin/chromium` أو `/usr/bin/google-chrome`
- اختياري: `pdftoppm` (حزمة poppler: `brew install poppler` أو `apt install poppler-utils`) لتحويل ملفات PDF إلى صور في سكربت اللقطات.

## التشغيل لأول مرة

```bash
cd web
corepack enable
pnpm install

cp .env.example .env
# املأ في .env:
#   APP_SECRET   ← ناتج: node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
#   ADMIN_EMAIL  ← بريدك
#   CHROMIUM_PATH ← مسار Chrome على جهازك (انظر أعلاه)
pnpm hash-password              # اكتب كلمة مرور (12 حرفًا على الأقل) والصق السطر الناتج في .env

# قاعدة البيانات: إحدى الطريقتين
docker compose up -d db         # Docker (DATABASE_URL في .env.example يعمل كما هو)
pnpm db:start                   # أو محليًا بلا Docker (ماك/لينكس)

pnpm db:migrate                 # إنشاء الجداول
pnpm db:seed                    # ثلاثة مشاريع تجريبية، ويطبع روابط تتبعها
pnpm dev                        # افتح http://localhost:3000/admin/login
```

ملاحظة عن `ADMIN_PASSWORD_HASH`: Next.js يفسّر علامة `$` داخل `.env`، لذلك يُحفظ الهاش بصيغة `\$argon2id\$...` كما يطبعه `pnpm hash-password`. لا تلصق الهاش بدون الشرطات المائلة.

**البيانات التجريبية:** `P-2026-0001` مشروع مرّ بكل المراحل حتى "الضمان" (عرض وإيصالان PDF)، و`P-2026-0002` عرض باليورو بانتظار العميل (جدول 30/40/30، وعميلة تتحدث الإنجليزية)، و`P-2026-0003` عميل محتمل جديد. لبداية نظيفة: `pnpm db:reset` (محلي بلا Docker)، أو مع Docker: `docker compose down -v && docker compose up -d db` ثم `pnpm db:migrate && pnpm db:seed`.

## جولة سريعة (خمس دقائق)

1. ادخل من `/admin/login`، وستجد شاشة "اليوم".
2. **العملاء ← عميل جديد** (البريد مهم: إليه تُرسل رموز التحقق ورابط التتبع)، ثم أنشئ مشروعًا من صفحة العميل.
3. في صفحة المشروع: **عرض جديد**، أضف البنود، ولاحظ جدول الدفع الافتراضي في الملخص (يمكن تعديله يدويًا)، ثم **حفظ المسودة**، ثم **إصدار وإرسال (PDF)**.
4. في بطاقة **رابط تتبع العميل**: **إنشاء رابط جديد** وانسخه. يظهر الرابط مرة واحدة فقط لأن النظام يحفظ هاشه لا الرابط نفسه (في التطوير: `pnpm portal-link P-2026-0002` يطبع رابطًا جديدًا).
5. افتح الرابط في نافذة خاصة: هذا ما يراه العميل. جرّب زر **English**.
6. رموز التحقق والرسائل تظهر في **صندوق الصادر** وفي طرفية الخادم ما دام `RESEND_API_KEY` فارغًا.

## تجربة البيع كاملًا على جهازك فقط

لتجربة القبول برمز التحقق، ورابط الدفع، وتسجيل الدفع والإيصال، وفتح الملفات النهائية: شغّل الخادم مؤقتًا بالمفتاح مفعّلًا دون تعديل `.env`:

```bash
SALES_ENABLED=true pnpm dev
```

لا تفعّل البيع في أي بيئة حقيقية قبل صدور التصريح (قاعدة ع3). القيمة `true` وحدها تفعّله.

## حل المشكلات

- **"محاولات فاشلة كثيرة" عند الدخول:** الحد 5 محاولات فاشلة كل 15 دقيقة لكل بريد (ولكل IP حين يكون `TRUSTED_PROXY` مضبوطًا)، والدخول الناجح يصفّر العداد. انتظر، أو في التطوير فقط: `pnpm db:psql` ثم `delete from rate_limits where key like 'admin-login%';`.
- **عنوان IP في الإنتاج:** اضبط `TRUSTED_PROXY` حسب الوكيل أمام التطبيق: `cloudflare` (مع قصر الوصول للخادم على عناوين Cloudflare) أو `nginx` (مع `proxy_set_header X-Real-IP $remote_addr;`). بدون ذلك يبقى عنوان IP مجهولًا، فتُتجاوز حدود المحاولات لكل IP ولا يُسجَّل IP مع قبول العرض. ويُنصح بحد حجم للطلبات في الوكيل (مثل `client_max_body_size 2m;` لكل المسارات عدا صفحات مشاريع لوحة التحكم التي تقبل رفع 25 ميغابايت).
- **"تعذّر إرسال البريد":** Resend رفض الرسالة (مفتاح خاطئ أو نطاق غير موثّق). لا يتغير شيء: الرابط السابق يبقى فعّالًا والرمز لا يُعتبر مُرسلًا. السبب مكتوب في سجل الخادم (`[email] delivery failed`).
- **"الدخول غير مُعدّ":** `ADMIN_EMAIL` أو `ADMIN_PASSWORD_HASH` فارغ، أو الهاش لُصق بلا `\$`.
- **ملف PDF لا يتولد:** تحقق من `CHROMIUM_PATH` (صفحة الإعدادات تعرضه). المستند يُصدر رغم ذلك، ويُعاد توليد PDF عند فتحه.
- **الرفع يفشل لملف كبير:** حد الرفع 25 ميغابايت؛ للملفات الأكبر استخدم رابطًا خارجيًا (Drive أو GitHub).
- **المنفذ 3000 مشغول:** `pnpm dev --port 3001` وغيّر `APP_BASE_URL` في `.env` ليطابقه (روابط التتبع تُبنى منه).

## قواعد للمطوّرين (ولوكلاء البناء)

- **Next.js 16 مختلف عن الإصدارات السابقة:** `params` و`searchParams` و`cookies()` و`headers()` كلها غير متزامنة (await). اقرأ الدليل المطابق للإصدار في `node_modules/next/dist/docs/` قبل كتابة كود جديد. (أوقفنا توليد `AGENTS.md`/`CLAUDE.md` تلقائيًا عبر `agentRules: false`.)
- **تغيير حالة المشروع** يتم فقط عبر `transitionProject()`؛ فهي تتحقق من الانتقال والشروط وتسجل الحدث.
- **أي عملية مالية** (قبول عرض، رابط دفع، تسجيل دفعة، إيصال) تمر عبر `assertSalesEnabled()`، وصفحة العميل تأخذ بياناتها من `getClientPortalView()` الذي يحجب روابط الدفع حين يكون البيع مطفأ.
- **المستندات المُصدرة لا تُعدّل** (مشغّل في قاعدة البيانات)؛ التصحيح بإشعار دائن `issueCreditNote()`.
- **المدير:** كل صفحة وكل إجراء وكل مسار تنزيل يبدأ بـ `await requireAdmin()`؛ التخطيط (layout) وحده ليس حماية.
- **العميل:** كل طلب في `/p/<الرمز>` (الصفحة والإجراءات والتنزيل) يعيد التحقق من الرابط عبر `verifyPortalToken()`. استخدم `<a>` لا `<Link>` داخل البوابة حتى لا يُحسب الجلب المسبق استخدامًا للرابط.
- **النماذج:** `ActionForm` + `SubmitButton` من `src/components/client.tsx`، والإجراء يعيد `ActionState` عبر `runAction()` (يحوّل الأخطاء إلى رسائل عربية للمدير)، أما إجراءات صفحة العميل فعبر `runClientAction()` (صياغة هادئة بلغة العميل، بلا أسماء إعدادات أو رموز أخطاء). إذا كان الزر يختفي بعد نجاح الإجراء، أبقِ `ActionForm` معروضًا واجعل محتواه فقط شرطيًا، حتى تبقى رسالة النتيجة ظاهرة.
- **الاتجاه:** أدوات Tailwind المنطقية (`ms-*`، `me-*`، `ps-*`، `pe-*`، `start-*`، `text-start`) بدل left/right. المبالغ بـ `<Money>`، والأرقام المرجعية والبريد بـ `<Ltr>`، وداخل النصوص المركّبة `ltr()` أو `isolate()` من `lib/bidi.ts`. نص المستخدم في الصفحة الإنجليزية يأخذ `dir="auto"`.
- **الأرقام** غربية (0–9) في اللغتين، والتواريخ بتوقيت العمل (`BUSINESS_TIMEZONE`) عبر `lib/ui/format.ts`.
- **البراند** يُقرأ من `src/config/brand.ts` فقط (الألوان متاحة كأصناف `bg-brand` و`text-brand` و`border-border`، والأيقونة تتولد منه).
- **صفحات العميل** تحت `/p/<الرمز>`، وصفحات المدير تحت `/admin`؛ رؤوس `noindex` و`Referrer-Policy: no-referrer` مضبوطة في `next.config.ts`.
